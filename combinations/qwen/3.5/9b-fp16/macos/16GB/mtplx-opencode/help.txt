NOTES FOR THIS COMBINATION

  PROVENANCE. Nothing here was measured by this repo, and no 16 GB Mac
  was used. Figures come from MTPLX 2.12.0's model catalog and the
  pack's own mtplx_runtime.json. No tok/s figure is quoted.

  WHO IT IS FOR. This is MTPLX's own pick for M1 and M2 16 GB Macs. It
  is the Qwen 3.5 9B Optimized Speed pack with every BF16 float tensor
  cast to FP16, because M1/M2 GPUs have no native BF16. On M3/M4/M5,
  MTPLX offers the BF16 build or MiMo V2.6 Qwen 9B instead; for a
  coding-tuned model there, see
  combinations/mimo/2.6/9b/macos/16GB/mtplx-opencode.

  The base model, not a coding fine-tune. Text only: this pack has no
  vision tower.

  THE WINDOW IS 20,480 TOKENS -- EXTRAPOLATED. No source states MTPLX's
  16 GB window for this FP16 pack; 20,480 is the release notes' 16 GB
  figure for its BF16 sibling, and the catalog puts this pack's peak at
  10.5 GiB against 10.0 for that sibling. The launcher passes the
  window explicitly, and MTPLX admits an explicit window past its own
  plan with a warning rather than refusing. On first run, read the
  server's "Memory plan" startup lines; if they say the window
  overcommits, lower CTX to the fit they report.

  Coding agents will compact often at this size: a system prompt, tool
  schemas and a couple of file reads can fill it.

  CONTEXT_LIMIT=20480 and OUTPUT_LIMIT=8192 go into the client's
  provider config (provider "mtplx-qwen35-9b"), written by the session
  command the first time each client is launched. For each client:

  OpenCode: limit.context 20480, limit.output 8192. OpenCode compacts
    from these; how much headroom it keeps back was NOT verified against
    the installed OpenCode.

  Pi: its compaction reserve DOES NOT FIT this window by default. Pi
    compacts when context > contextWindow - reserveTokens, and the
    default reserveTokens is 16384 -- so at 20,480 it compacts past ~4k
    tokens, i.e. almost every turn, and its default keepRecentTokens
    (20000) is the whole window. The installer does not touch Pi's
    settings. Add a per-model override to ~/.pi/agent/settings.json:

      "compaction": {
        "modelOverrides": {
          "mtplx-qwen35-9b/mtplx-qwen35-9b-optimized-speed-fp16": {
            "reserveTokens": 8192,
            "keepRecentTokens": 4096
          }
        }
      }

    Those two values are a starting point matched to OUTPUT_LIMIT, NOT a
    tested setting.

  Thinking tokens count against max_tokens (8192). Empty replies mean
  the budget went inside <think>. THINKING=0 turns thinking off.

  REASONING_EFFORT does nothing for this model: its chat template reads
  only enable_thinking. Any value other than 'default' is rejected.

  CREDIT. Model: Qwen3.5-9B by the Qwen team (Apache 2.0). MTPLX pack
  and FP16 conversion: Youssofal.

EXAMPLES

  mtplx-qwen35-9b-fp16-server                   # coding profile
  THINKING=0 mtplx-qwen35-9b-fp16-server        # no thinking tokens
  CTX=16384 mtplx-qwen35-9b-fp16-server         # if the plan says 20k overcommits
