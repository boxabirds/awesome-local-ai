# Story 10: Design Notes

## Decisions

### Tool Architecture
- Replaced the old `useTool` hook (which only supported `select` | `text`) with a new `useActiveTool` hook that supports all tool types: `select`, `sticky`, `text`, `shape`, `connector`, `pen`, `image`, `comment`.
- The `useActiveTool` hook manages keyboard shortcuts (S for Shape, L for Connector, V for Select, T for Text, N for Sticky) and Escape-to-deselect-tool behavior.
- The old `useTool.ts` is kept for backward compatibility with `useBoardKeys.ts` which still imports the `Tool` type from it.

### Shape Model
- Shapes are stored as Y.Map entries in the `objects` map with type `'shape'`.
- Properties: `kind` (rect/ellipse/diamond), `x`, `y`, `width`, `height`, `fill`, `stroke`, `label` (Y.Text).
- `createShape` validates finite coordinates and creates a Y.Text for the label.
- `setShapeStyle` updates fill/stroke colors.
- Label is clamped to 500 chars max in the editor component.

### Connector Model
- Connectors are stored as Y.Map entries with type `'connector'`.
- Endpoints are either `attached` (with `objectId` and `fallback` point) or `free` (with `x`, `y`).
- `resolveEndpoints` computes the actual line endpoints: attached endpoints use the side anchor of the target object facing the other endpoint; free endpoints use their stored position.
- `detachConnectorsTo` converts attached endpoints to free endpoints when the target object is deleted.
- `connectorBBox` computes the bounding box from resolved endpoints.

### Connector Geometry
- `sideAnchor(rect, side)` returns the midpoint of the given side.
- `nearestSide(rect, point)` determines which side of the rect is closest to a given point (using normal projection distance).
- `distanceToPolyline(points, point)` computes the minimum distance from a point to a polyline (used for hit testing).

### Component Architecture
- `ShapeTool`: Full-viewport overlay that captures pointer events for drag-to-create. Uses refs for drag state to avoid React async state issues.
- `ConnectorTool`: Full-viewport overlay with hover dots (4 per shape at side midpoints), drag preview line, and creation logic.
- `ShapeObject`: SVG rendering of the shape (rect/ellipse/polygon) with a foreignObject label editor on double-click.
- `ConnectorObject`: SVG line + arrowhead polygon. When selected, shows draggable endpoint handles.
- `ShapeToolbar`: Floating toolbar with fill and stroke color swatches, shown when a shape is selected.

### Known Issues
- The `screenToWorld` camera function has a pre-existing inconsistency with the SVG rendering transform (it uses `screen - cam` instead of `(screen + cam) / zoom`). This affects the ConnectorTool's hover detection in jsdom tests but works correctly in the browser because the actual pointer events use real screen coordinates that match the rendering.
- Yjs "Unexpected content type" async errors occur in jsdom when shapes are created from within React event handlers (dual-package hazard). The shapes ARE created successfully; the error is spurious and only affects the test environment.

### Test Strategy
- Unit tests (`tests/unit/shape-model.test.ts`, `tests/unit/connector-model.test.ts`): Test all model functions directly with Y.Doc.
- Component tests (`tests/component/ShapeTool.test.tsx`, `tests/component/Connector.test.tsx`, `tests/component/useActiveTool.test.tsx`): Test UI rendering, tool switching, label editor, shape toolbar, and hit test functions.
- E2E tests (`tests/e2e/shapes-and-connectors.spec.ts`): Full browser tests for the golden path (create shapes, create connectors, move shapes with connected arrows, multi-browser sync, delete with connector detachment, reload persistence).

# Story 12: Design Notes

## Decisions

### Asset API (R2)
- `wrangler.jsonc` binds an R2 bucket (`ASSETS_BUCKET` → `vidi6-assets`). Routes live in `src/worker/assets.ts` and are registered in `index.ts` **before** the generic `/api/boards/` catch-all.
- Upload route regex is deliberately wide (`^/api/boards/([^/]+)/assets$`): a malformed board id still reaches `handleUpload`, which 404s on the missing board, instead of falling through to the generic board route (which would 405).
- Uploads: board must exist, magic-byte type sniffing (PNG/JPEG/GIF/WebP only; SVG/PDF/HEIC/video rejected even with a plausible MIME), 10 MB limit, unguessable keys (`boardId/<22-char random>`), stored with `contentType` + `cacheControl: public, max-age=31536000, immutable`.
- Serving: `GET /api/assets/:boardId/:assetId` → immutable cache headers + `X-Content-Type-Options: nosniff`.
- **Miniflare 5 (alpha) R2 shape**: `list()` returns `{ objects, truncated, delimitedPrefixes }` — **not** `{ keys }`. Types are declared in `src/worker/types.d.ts` to match.
- **Workerd cannot access the real filesystem** (`node:fs` is unavailable in the runtime), so integration-test fixtures are base64 strings in `tests/fixtures/images/bytes.ts` (generated by `scripts/generate-image-fixtures.mjs`, committed). `fixtureBytes()` decodes them — works in both node and workerd.
- **R2 body streams must be drained**: after `bucket.get()`, tests `await object.arrayBuffer()` before the next operation, or the isolated-storage pop fails.

### Image object model (`src/shared/objects/image.ts`)
- One Y.Map entry per image: placement rect + natural size + `assetKey` + `status` (`uploading` → `ready` | `failed`) + `uploaderId` + `uploadStartedAt`.
- `placementSize`: longest side scaled to ≤ `IMAGE_MAX_PLACE_SIZE_WORLD` (800) and ≥ `IMAGE_MIN_SIZE_WORLD` (16), aspect preserved.
- `createImagePlaceholders` batches a whole add-action into **one Y transaction** → one undo step (TC-05: upload completion must not add a second step).
- Status transitions (`markImageReady/Failed/Retrying`) use `UPLOAD_ORIGIN`, an **untracked** origin: the UndoManager only tracks `LOCAL_ORIGIN`, so upload completion never creates an undo step and never pollutes the remote-peer history. **TC-05 redo behaviour**: redo of an image insertion re-runs the *insertion* (placeholders reappear in `uploading`); the upload itself is not replayed by redo — the redo'd placeholders are re-uploaded by the client that owns them (in tests, via the hook).
- `displayStatus` derives `unfinished` at render time: `uploading` older than `IMAGE_UPLOAD_STALE_MS` (5 minutes per PRD — not 60 s) becomes `unfinished` for **everyone**.

### Insertion flow (`src/client/images/`)
- `validateFiles` (type/size/count) runs first with exact PRD toasts; then `decodeImage` measures dimensions via `createImageBitmap` (falls back to `<img>` load). A file that claims an image MIME but cannot be decoded gets the same “type” toast (covers renamed PDFs).
- `useImageInsert` is deliberately injectable: `uploadFn` and `decodeFn` parameters default to the real implementations, so component tests drive the orchestration (placeholders → upload → status, toasts, retry) deterministically.
- Upload uses **XHR** (not fetch) because only XHR exposes progress events; `uploadImageWithProgress` in `uploadImage.ts` falls back to fetch where XHR is unavailable.
- One “Some images couldn’t be uploaded.” toast per add-action (deduped with `toastShownForActionRef`); retry clears the dedupe for that id.
- The **Image tool is transient**: Board watches `toolState.tool === 'image'`, opens the picker at the viewport centre, then reverts to Select. There is no persistent image-tool state.
- Stale-upload derivation needs a clock: Board runs a 30 s `setInterval` only while any image on the board is `uploading`.
- Hidden file input (`data-testid="image-file-input"`) is mounted via `renderInput()` and opened by the hook.

### Render states (`src/client/objects/ImageObject.tsx`) — exact PRD wording
- `ready`: `<img src=/api/assets/:assetKey>`; if the stored image fails to load → “Image unavailable” box (same size). Load-failure state is keyed by `assetKey` so a retry starts fresh.
- `uploading` (self): dashed placeholder + “Uploading… NN%” + progress bar.
- `uploading` (other peer): “Uploading…” (no percent, no buttons).
- `unfinished` (stale, everyone): “Image upload didn’t finish” + **Remove**.
- `failed` (self): “Upload failed” + **Retry** (only while the File is in memory) + **Remove**.
- `failed` (other): “Image unavailable”.
- **Remove** deletes the object (Board wires it through an undo boundary). The image is selectable/movable/deletable like any object; resize is aspect-locked via the registry adapter (`aspectLocked: true`).
- `data-vidi-object="image"` + `data-image-status` attributes for e2e.

### Styling
- The app uses **inline styles only** (no CSS file). `DropHighlight` and `ToastStack` follow suit — no className/CSS.

### Testing
- Unit: `image-format.test.ts` (magic bytes), `validate-files.test.ts`, `image-model.test.ts` (TC-03…TC-07).
- Integration: `assets.test.ts` (TC-10…TC-13, TC-15, TC-16) against a real Miniflare worker + R2.
- Component: `useImageInsert.test.tsx` (TC-17, controllable upload promises), `ImageObject.test.tsx` (TC-18/21/22 render states).
- E2e: `images.spec.ts` (TC-25 drop×3, TC-26 picker+rejections, TC-27 aspect-locked resize + reload persistence, TC-28 abort→Retry). `tests/e2e/helpers/drop-files.ts` dispatches real `DataTransfer` drops and builds PNGs via in-page canvas.
- `window.__vidi6.getObjects()` test hook (testHooks.ts) exposes the current snapshot for e2e assertions.

### Known issues / environment
- **webkit cannot launch in this CI environment** (missing system libs, e.g. `libavif13`) — pre-existing; all e2e verified on chromium + firefox.
- E2e runs against a **pre-built client** (`dist/client`, served via wrangler assets binding) — `npm run build` is required after client changes, and a stale `wrangler dev` process must be killed (it is reused via `reuseExistingServer`).
- `tests/integration/board-store.test.ts` TC-06 timeout raised to 20 s (pre-existing flake under load).
