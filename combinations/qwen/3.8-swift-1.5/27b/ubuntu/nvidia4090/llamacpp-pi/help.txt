WHY THIS MODEL (Swift 1.5)
  UkisAI's second reasoning-efficient retrain of Qwen3.8-27B. Vendor claims
  (not reproduced here): stronger than Swift 1.0 on coding and agentic tasks,
  58.5% fewer thinking tokens than base; LiveCodeBench v6 76.76% -> 81.71% and
  Terminal-Bench 2.1 69.21% -> 72.13% against the base model.

MTP / SPECULATIVE DECODING
  The MTP head is inside the GGUF, so the launcher uses --spec-type draft-mtp
  with --spec-draft-n-max 4 and no sidecar. "MTP head missing" at install is
  expected. Unlike Swift 1.0 (Q8_0), the head's projection is Q4_0: acceptance
  is not measured yet. Confirm it is live: grep the server log for "creating
  MTP draft context" and "draft acceptance".

NOTE ON THE FILE'S NAME
  The GGUF's own metadata says "Miroslav 1.0". It comes from
  ukisai/Swift-1.5-Qwen3.8-27B-GGUF; the repository, not that label, is what
  identifies this combination.

GOTCHA: THINKING MODE AND max_tokens
  Reasoning is billed against max_tokens; a small max_tokens returns an empty
  answer with finish_reason "length". Give agents a generous max_tokens.

SECURITY
