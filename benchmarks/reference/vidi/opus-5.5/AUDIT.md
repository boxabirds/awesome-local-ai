# Opus 5.5 reference: delivery audit

The audit follows [`benchmarks/vidi/audit.md`](../../../vidi/audit.md), the same rubric every setup gets. Four independent auditors (fresh Opus 5.5 subagents) checked the delivered code against the spec, and the agents' completion claims against the code. They worked by reading the code, reading the held-out results, and running targeted checks on the build machine. The rows below were merged and checked afterwards; one fault found under two stories counts once.

## Count

| Category | Rows |
|---|---|
| **functional** (behaviour differs from the PRD) | **4** |
| missing-test | 1 |
| weak-test | 0 |
| false-claim | 0 |
| design-deviation (no user-visible effect) | 9 |

The held-out suite, after the suite fixes below, scored this build **73/75**. The 2 failing tests are functional fault 1. A second full run scored 72/75: one story 12 file-chooser test timed out once, the intermittent case listed below.

**Were the agents' completion claims true?** Yes, with disclosed exceptions. No report claimed something that wasn't done. Every gap the audit found was either recorded by the agent itself in its report or `NOTES.md`, or was a behaviour the agent believed was right:
- the button-focus exemption for Delete (fault 1);
- the damaged-log limit (fault 2);
- WebKit not run;
- tests not written first (5 design-deviation rows).
